Часть 1. На основе анализа чата разработчиков и технической документации, ниже представлен подробный справочник по движку OkayCMS, структурированный для программиста.

--------------------------------------------------------------------------------
1. Архитектура и стек технологий
Язык и шаблонизатор: Движок написан на PHP (без использования тяжелых фреймворков типа Laravel/Symfony в ядре). Для фронтенда используется Smarty (.tpl).
Структура ядра (Okay/Core): Основные классы ядра (ManagerMenu, Response, Phone, Discount) находятся в DI-контейнере.
Основные типы классов: Система разделена на контроллеры, сущности (Entities), Helpers, Requests и маршруты (Routes).
Dependency Injection (DI): Инстансы классов содержатся в DI-контейнере. Сервисы регистрируются в файлах services.php, requests.php и helpers.php внутри Okay/Core/config/.
2. Среда и системные требования
Версия PHP: Рекомендуются 7.4 или 8.0 . Версии выше 8.0 могут вызывать ошибки из-за устаревших функций в сторонних библиотеках .
База данных: Оптимально использовать MySQL 5.7 или MariaDB.
Веб-сервер: Движок отлично работает на Apache. Для Nginx требуются специфические настройки конфига, которые лежат в папке docs/nginx/. Использование LiteSpeed может вызвать проблемы с обработкой изображений.
3. Работа с данными (Entities)
Класс Entity: Все сущности должны наследоваться от Okay\Core\Entity\Entity.
Обязательные свойства: В классе необходимо указать $table (название таблицы), $tableAlias и $fields (список полей для выборки).
Мультиязычность: Реализуется через свойства $langTable, $langFields и $langObject. Данные распределяются между основной таблицей (например, ok_products) и языковой (ok_lang_products).
Запросы: Для работы с БД используются классы QueryFactory (Insert, Select, Update, Delete) или SqlQuery для кастомных запросов.
Фильтры и сортировки: Поддерживаются "магические" фильтры (автоматическая фильтрация по полям БД) и пользовательские (метод customFilter()). Сортировка перегружается через метод customOrder().
4. Контроллеры и маршрутизация
Контроллеры: Делятся на фронт-контроллеры (Okay\Controllers\AbstractController) и бек-контроллеры (Okay\Admin\Controllers\IndexAdmin).
Маршруты (Routes): Описываются в routes.php. Система использует регулярные выражения для парсинга URL и передачи параметров в методы контроллеров.
Генерация URL: Используется метод Router::generateUrl() или Smarty-плагин {url_generator}.
Переопределение роутов: В новых версиях можно использовать параметр 'overwrite' => true в описании маршрута, чтобы заменить системный роут модульным.
5. Расширение функционала (Extenders)
Точки входа: Расширять можно методы, где вызван ExtenderFacade::execute(). Хелперы и реквесты покрыты экстендерами максимально.
Режимы работы:
ChainExtender: Последовательно передает результат работы одного метода другому. Метод экстендера обязательно должен возвращать результат.
QueueExtender: Поочередный вызов без передачи результата.
Регистрация: Экстендеры описываются в Init.php через registerChainExtension или registerQueueExtension.
6. Шаблонизация и дизайн
Smarty плагины: Бывают функциями (Okay\Core\SmartyPlugins\Func) и модификаторами (Okay\Core\SmartyPlugins\Modifier). Регистрируются в SmartyPlugins.php.
Подключение ресурсов: JS и CSS файлы регистрируются через классы Okay\Core\TemplateConfig\Js и Css. Параметр setIndividual(true) позволяет подключать файл отдельно от общего бандла.
WebP: В Smarty доступен модификатор |webp, который автоматически генерирует и подставляет изображения в формате WebP.
TPL Modifiers: Позволяют изменять стандартные шаблоны без правки файлов. Описываются в module.json. Доступные действия: append, prepend, replace, remove, appendBefore, appendAfter.
7. Полезные инструменты разработчика
Debug Mode: Включается в config/config.php (debug_mode = true). Позволяет видеть ошибки PHP и SQL.
Логи: Системные ошибки пишутся в папку Okay/log/ в файлы формата app-YYYY-MM-DD.log.
Планировщик (Cron): Использует класс Okay\Core\Schedule. Для работы всех задач по расписанию (например, обновление курсов валют или остатков НП) нужно настроить на сервере запуск файла ok раз в минуту: * * * * * php /path/to/site/ok scheduler:run.
Кэширование:
Скомпилированные шаблоны — в папке compiled/.
Сжатые JS/CSS — в папке cache/.
Кэш роутов — в таблице ok_router_cache (его очистка может ускорить импорт, но сбросит ЧПУ).
Service Locator: Используется для получения сервисов из DI-контейнера в местах, где недоступна инъекция: ServiceLocator::getService(ClassName::class).
8. Работа с базой данных и миграции
Миграции в модулях: Выполняются в методе install() класса Init.php. Методы: migrateEntityTable() (новая таблица), migrateEntityField() (добавление столбца в существующую), migrateCustomTable() (таблица связей).
Auto-increment: Если нужно сбросить нумерацию заказов, используется SQL запрос: ALTER TABLE ok_orders AUTO_INCREMENT = 1;.
Важное замечание: При добавлении полей в существующие сущности через миграцию, их нужно зарегистрировать в методе init() через registerEntityField(), чтобы они попали в выборку SELECT.
9. Интеграция с внешними системами
1С / BAS: Модуль интеграции OkayCMS/Integration1C работает по протоколу CommerceML2 . Кастомизация обмена возможна через создание классов-оверрайдов в Okay\Modules\OkayCMS\Integration1C\Integration\Export\Overrides.
API: Полноценного REST API "из коробки" в системе долгое время не было, часто требуются кастомные решения на базе контроллеров .
Этот справочник аккумулирует ключевые технические аспекты, упомянутые опытными разработчиками в процессе обсуждения реальных задач и проблем.



Часть 2. Этот справочник составлен исключительно на основе переписки разработчиков в чате и предназначен для помощи в создании собственных модулей для OkayCMS (начиная с версий 3.x и 4.x).

--------------------------------------------------------------------------------
1. Общая философия и архитектура
Модульность: Основная идея версий 3.8.1+ заключается в том, чтобы не править ядро напрямую. Это позволяет обновлять систему, не теряя доработки.
Структура: Система основана на PHP и использует шаблонизатор Smarty (.tpl).
Изоляция: Код модуля должен быть инкапсулирован в отдельной папке, что позволяет легко переносить его между проектами.
2. Структура и размещение модуля
Все модули должны располагаться по пути: Okay/Modules/ИмяВендора/НазваниеМодуля/.
Основные файлы и директории:
Init/Init.php: Главный конфигурационный класс. Должен наследоваться от AbstractInit. Содержит методы install() (выполняется один раз при установке) и init() (выполняется при каждом запуске системы).
Init/module.json: Мета-информация (версия, автор, модификации TPL).
Init/routes.php: Регистрация маршрутов (URL) модуля.
Init/services.php: Регистрация сервисов модуля в DI-контейнере.
Backend/Controllers/ & Controllers/: Контроллеры админ-панели и клиентской части.
design/ & Backend/design/: Шаблоны, стили и скрипты модуля.
3. Регистрация и установка
Загрузите папку модуля на сервер.
В админ-панели перейдите в раздел "Модули" и нажмите "Установить".
Для того чтобы модуль появился в меню, используйте метод extendBackendMenu() в Init.php.
Если нужно предоставить доступ к модулю менеджеру, это настраивается через разрешения (permissions) в таблице ok_managers или через метод addBackendControllerPermission().
4. Работа с базой данных (Миграции)
Для изменения структуры БД из модуля используются методы в install() класса Init.php:
migrateEntityField: Добавляет столбец в существующую таблицу ядра (например, ProductsEntity).
migrateEntityTable: Создает новую таблицу для сущности модуля.
migrateCustomTable: Создает произвольную таблицу (например, таблицу связей).
Регистрация поля: После добавления столбца в таблицу ядра его нужно зарегистрировать методом registerEntityField() в init(), иначе система не будет его "видеть".
5. Расширение логики (Extenders)
Экстендеры позволяют вмешаться в работу методов хелперов, реквестов и сущностей, где вызван ExtenderFacade::execute().
ChainExtender (цепочный): Экстендер получает результат работы предыдущего метода, может его изменить и обязательно должен вернуть результат дальше.
QueueExtender (очередь): Методы выполняются последовательно.
Пример: Для изменения данных заказа после оформления можно подключиться к методу finalCreateOrderProcedure в OrdersHelper.
6. Модификация шаблонов (TPL Modifiers)
Функционал позволяет изменять стандартные .tpl файлы, не трогая их оригиналы. Все правки описываются в Init/module.json в блоке modifications.
Методы поиска: Работа с файлом идет как с DOM-деревом (поиск нод), а не просто как с текстом.
Действия: append (в конец), prepend (в начало), appendBefore, appendAfter, replace (замена открывающей ноды), remove.
Важно: После внесения изменений в module.json необходимо очистить папку compiled, чтобы изменения вступили в силу.
7. Подключение стилей и скриптов
OkayCMS собирает и минифицирует JS и CSS через специальные файлы:
Регистрация происходит в design/js.php и design/css.php (для фронта) или Backend/design/... (для админки).
Для индивидуального подключения файла (вне общего бандла) используйте метод setIndividual(true).
В самом шаблоне можно использовать плагины {js} и {css}.
8. Настройки модуля (Settings)
Для хранения простых настроек (например, API-ключей) лучше использовать системную таблицу ok_settings .
В PHP: $this->settings->set('param_name', $value) и $this->settings->get('param_name') .
В Smarty: Доступ к настройкам осуществляется напрямую через {$settings->param_name}.
9. Полезные советы из чата
Дебаг: Для отладки модификаций TPL включите smarty_force_compile в config.php (только для разработки!).
Логи: Ошибки системы ищите в Okay/log/.
Кэш: Если изменения не видны, чистите compiled/ (шаблоны) и cache/ (стили/скрипты).
Изображения: OkayCMS создает нарезанные изображения (resized) автоматически при первом обращении к ним, если в папке originals есть исходник.
Обновление БД: Если в новой версии модуля изменилась структура БД, в админке рядом с модулем появится кнопка для обновления структуры.
